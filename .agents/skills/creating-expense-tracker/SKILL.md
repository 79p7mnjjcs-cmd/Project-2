# Создание списка личных расходов

Создавай простой локальный список расходов. Прочитай AGENTS.md, текущий код и согласованный план. Вызов навыка без конкретной задачи не разрешает менять приложение. Не начинай реализацию плана, который ещё ожидает проверки пользователя.

## Состав по умолчанию

| Часть | Содержание |
| --- | --- |
| Форма | Название, сумма, дата, кнопка «Добавить» |
| Список | Название, сумма, дата, удаление отдельной записи |
| Итог | Сумма всех трат в одной валюте |
| Хранение | localStorage с версией схемы |

Валюта по умолчанию — рубли; сообщи это допущение. Явные требования пользователя имеют приоритет. Не добавляй категории, графики и другие функции без запроса.

## Правила

- HTML5, CSS3 и обычный JavaScript; без сборки, фреймворков, библиотек и CDN.
- Без регистрации, авторизации, сервера и серверной БД.
- Папку assets не менять, не удалять и не перемещать.
- Комментарии писать по-русски. Длинные функции разделять по задачам.
- Сохранять части интерфейса, которые пользователь просил оставить, включая приветствие и конфетти.

## Порядок реализации

1. Сделай подписанные поля, пустое состояние, доступные кнопки и видимый фокус. Добавление работает кнопкой и Enter. Ошибки показывай возле полей; при ошибке сохраняй ввод.
2. Храни запись как `{id, title, amountMinor, date}`: уникальный id, непустое название без крайних пробелов, целые копейки, корректная календарная дата YYYY-MM-DD. Дата по умолчанию местная: не используй UTC toISOString().
3. Принимай точку или запятую и до двух знаков после разделителя. Отклоняй ноль, отрицательные значения, экспоненты, лишний текст и выход за безопасный диапазон. Контролируй диапазон итоговой суммы. Отображай деньги без потери копеек; пользовательский текст выводи через textContent.
4. Удаляй по id: одинаковые покупки допустимы. Храни объект `{version: 1, expenses: [...]}`. После изменений сохраняй список; при открытии проверяй версию и структуру каждой записи. Обрабатывай ошибки доступа, JSON.parse и записи в localStorage. При повреждённых данных или неизвестной версии заблокируй запись в исходный ключ и продолжи в памяти; сброс возможен только по явному действию пользователя. При отказе хранения оставь работу в памяти и явно сообщи, что изменения не сохранятся после закрытия.

## Пример разбора рублей

```js
function parseRubles(value) {
  const match = /^(\d+)(?:[.,](\d{1,2}))?$/.exec(value.trim());
  if (!match) throw new Error('Введите сумму, например 12,50');
  const minor = BigInt(match[1]) * 100n
    + BigInt((match[2] || '').padEnd(2, '0'));
  if (minor <= 0n || minor > BigInt(Number.MAX_SAFE_INTEGER)) {
    throw new Error('Сумма вне допустимого диапазона');
  }
  return Number(minor);
}
```

## Проверка результата

Открой приложение и проверь консоль. Добавь «Продукты», 12,50, сегодняшнюю дату: запись и итог должны показать 12,50 ₽. Перезагрузи страницу — запись остаётся. Добавь такую же покупку, удали одну — вторая остаётся. Проверь пустой ввод, 0, -1, 12abc, три десятичных знака, повреждённый JSON и отказ хранилища. Проверь клавиатуру и ширину 360 px; assets не изменена. Если есть сохранённое приветствие и конфетти, проверь их работу.

В отчёте перечисли изменения, реальные проверки и ограничения. Если браузер недоступен, укажи, что браузерные проверки не выполнены. Коммиты и PR делай только в рамках разрешённой задачи.

## Частые ошибки

- parseFloat принимает начало строки: нужен строгий разбор.
- Дробные рубли дают ошибки округления: считай в целых копейках.
- Удаление по названию затрагивает одинаковые записи: используй id.
- Успешное добавление на экран не доказывает сохранение: проверь перезагрузкой.
